04 · Enriquecimento do cliente

Três fontes
para um cadastro completo.

BLING

Vem em todo pedido

  • Nome e CPF ou CNPJ
  • Endereço de entrega completo
  • Inscrição estadual, quando cadastrada
  • Itens, valores e pagamento
BRASIL API

Só para CNPJ

  • Razão social e nome fantasia
  • Endereço da Receita e CEP
  • Telefone e CNAE
  • Situação cadastral (ativa, baixada)
REGRA FIXA

Definido pela Jumil

  • Tipo de cliente pelo documento
  • Mercado interno
  • Situação ativa
  • Origem Mercado Livre

Atenção

A Brasil API não atende CPF e não traz inscrição estadual. Comprador pessoa física entra só com os dados do Bling. E o Mercado Livre não repassa telefone nem e-mail do comprador ao Bling.

07 · Pontos para corrigir

O que encontramos
na API e na documentação.

Bloqueiam a fase 1

  • Cadastro de cliente: erro 500, o código do cliente e as outras colunas obrigatórias não são preenchidos
  • Pedido: a documentação pede orderId, customerCnpj e sku; a API só aceita zeittenOrderId, cnpj, fullAddress e code
  • Pedido aceito para CNPJ que não é cliente
  • Status e histórico não mostram pedido "Não Integrado"; cancelamento devolve só true

Afetam a fase 2

  • Estoque ignora o filtro: pedimos a 2769160 e veio a 0103562
  • Estoque leva cerca de 28 s; sem filtro, passa de 30 s sem resposta
  • Prazo de entrega: a documentação diz sku, a API aceita code
  • Prazo de máquina parada (14/12) maior que o padrão (24/11)
  • Histórico ignora o filtro por data

Segurança: a API roda sem HTTPS, e a chave do Mercado Livre também lê descontos, condições de pagamento e clientes do sistema comercial. Recomendamos HTTPS e uma chave com acesso só ao e-commerce.

O que a API já tem

  • Preço, NCM e prazo de reposição
  • Status do pedido com data de entrega e campo para o XML da nota

O que falta para sincronizar

  • Data da última alteração, para ler só o que mudou
